# 模拟联合国历史委员会 · 会场控制台

> **全栈 v2 · 可部署到 Vercel**
> 前端 React + Vite；后端 Hono + libSQL（本地 SQLite 文件 / 线上 Turso）。
> 支持主席与代表账号、会议时钟、定时/危机事件、文件提交、已读状态与跨设备同步。
> 更新：2026-11-02

---

## 一、页面

| 页面 | 功能 |
| --- | --- |
| **主页** | 会议主题（主席可编辑）、作者小红书号 + 二维码、会议概览、功能导览 |
| **席位** | 代表团/席位增删改、票权 ≥0、全局否决、出席规则、票数统计 |
| **会期** | 会期/议题增删改、设为当前、顶栏显示当前会期与议题 |
| **投票** | 决议增删改、多数规则、否决国、点名计票、半圆图、历史快照 |
| **时间** | 会议时钟、设定时间、开始/暂停、流速（数字输入）、危机暂停 |
| **事件** | 发布/修改/删除、收件账号、定时发布、危机、代表已读、顶部弹窗 |
| **文件** | 代表提交（≤2MB）、主席查看全部、代表只看自己、已读切换、下载 |
| **设置** | 默认规则、跳过表决步骤、账号管理（主席）、存档导出/导入/清空 |

每个页面右上角都有会议时间戳；只有主席可以在「时间」页修改。
所有页面顶部有超链接导航：主页 / 席位 / 会期 / 投票 / 时间 / 事件 / 文件 / 设置。

## 二、账号与权限

- 初始主席账号：**123456 / abcd**。部署后请立即在「设置 → 账号管理」重置密码。
- 代表账号由主席在「设置 → 账号管理」创建，代表不能注册。
- 主席：全部编辑、时间控制、事件管理、查看全部文件、标记文件已读、账号管理、数据管理。
- 代表：可查看所有页面；可提交文件；可查看发给自己的事件并切换自己的已读；不能编辑任何会议数据。
- 所有写操作服务端二次校验角色。

主席从其他页面点击「事件」或「文件」时，会弹出：

> 是否确认进入事件界面？请确保未公屏投放给代表。

取消则留在原页面；代表进入不触发；直接输入 URL 不触发。

## 三、时间 / 事件 / 文件

### 时间
- 服务端权威时间：`now_ms + rate + running + anchor`。
- 主席可设定当前时间、开始/暂停流动、输入阿拉伯数字设置流速（如 1、2、0.5、100）。
- 危机事件发布时立刻暂停时间；主席在时间页「解除危机暂停」后再手动开始。
- 定时事件按会议时间发布，不按现实时间。

### 事件
- 字段：收件代表账号（多选）、事件时间、标题、内容、是否危机。
- 已到时间：自动发布给收件代表；未到：主席看到「定时发布」，代表看不到。
- 代表在任意页面都会看到顶部圆角提醒（时间 + 标题 + 查看 + 标为已读）。
- 事件边上按钮在「未读 / 已读」间切换；主席看到已读人数。
- 危机事件发布后暂停时间；取消该事件的危机标记会解除暂停状态（不自动恢复流动）。

### 文件
- 代表提交任意文件（≤2MB），标题可自定义。
- 主席看到全部提交，可下载、标记「未读/已读」。
- 代表只看到自己的文件，显示「主席团未读/已读」。
- 文件存储在数据库中。

## 四、技术架构

```text
React 19 + Vite 8  ──fetch /api/*──▶  Hono 4（Vercel Serverless / Node）
                                          │
                                          ▼
                                   Turso（线上）/ .data/mun.db（本地）
```

- 认证：Cookie 会话（HttpOnly、SameSite=Lax、线上 Secure），密码 scrypt 加盐。
- 数据：`meeting` 保存会议状态 JSON + revision；`time_state`；`events` + `event_recipients`；`files`；`accounts` + `sessions`。
- 实时：前端每 2.5 秒轮询 `/api/bootstrap`；事件弹窗最多延迟约 2.5 秒。
- 首次请求自动建表并写入初始主席账号，无需手动执行 SQL。

## 五、本地运行

要求 Node.js **22.18+**（推荐 24 LTS）。

```bash
pnpm install

# 终端 1：API（8787）
pnpm dev:api

# 终端 2：前端（5173，已代理 /api）
pnpm dev
```

打开 <http://127.0.0.1:5173>，使用 `123456 / abcd` 登录。
本地数据库：`.data/mun.db`；重置：停止 API，删除 `.data/`，重启 API。
生产构建：`pnpm build`（产物 `dist/`）。

当前预览：<http://127.0.0.1:5173>（API 8787 已启动）。

## 六、部署到 Vercel

详细步骤见 **[部署指南.md](部署指南.md)**。

1. Turso 创建数据库，取得 `TURSO_DATABASE_URL` 与 `TURSO_AUTH_TOKEN`。
2. 项目推送到 GitHub，在 Vercel 导入（框架 Vite，build `pnpm build`，output `dist`）。
3. 在 Vercel 配置两个环境变量。
4. Deploy；首次访问用初始主席账号登录，修改密码并创建代表账号。

`api/index.ts` 会自动成为 Serverless Function，无需额外服务器配置。

## 七、数据与安全

- 数据在 Turso，换设备登录同一网址即可继续。
- JSON 存档只包含会议规则（主题、席位、会期、决议）；账号、事件、文件不包含在内。
- 文件占数据库空间，单文件 ≤2MB；会后请主席下载留存。
- 不要把主席页面投屏给代表；直接输入事件/文件 URL 不会触发确认弹窗。
- 代表只能提交文件、查看页面、切换自己的事件已读状态。

- `vite build` 通过：62 模块，JS 316 KB（gzip 94 KB），CSS 48 KB（gzip 10 KB）。

- 浏览器端到端（1440px + 390px）：登录登出、主席与代表权限、投屏确认、事件表单与弹窗、已读切换、时间控制、文件列表、手机菜单；无运行时异常。
- 演示截图：`正式文件/预览/`。

## 九、已知边界

- 2.5 秒轮询，不是 WebSocket。
- 定时事件只在有页面轮询时发布；无人打开时会在下一个人访问时补发。
- 文件 ≤2MB，无预览、无删除、无版本。
- 只有一个主席角色；代表不能自行改密码，需主席重置。
- 无审计日志、撤销、回收站；删除前请确认。
- 事件只通过网页提醒，没有邮件/微信推送。
