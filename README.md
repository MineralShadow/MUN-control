# 模拟联合国历史委员会 · 会场控制台

> **全栈 v2 · 可部署到 Vercel**
> 前端 React + Vite；后端 Hono + libSQL（本地 SQLite 文件 / 线上 Turso）。
> 支持多会场、多主席、会场切换、公开/秘密事件、Web Push、会议主持、文件权限、线上存档与跨设备同步。
> 更新：2026-11-03

---

## 一、页面

| 页面 | 功能 |
| --- | --- |
| **主页** | 会议主题（主席可编辑）、作者小红书号 + 二维码、会议概览、功能导览 |
| **席位** | 代表团/席位增删改、代表团总体计票 / 代表计票、代表票权、全局否决、出席规则 |
| **会期** | 会期/议题增删改、设为当前、顶栏显示当前会期与议题 |
| **会议主持** | 编辑动议类型；选择动议国、主题、总时长、单位时长与发言名单；实时动议计时 |
| **投票** | 决议增删改、多数规则、否决国、点名计票、半圆图、历史快照 |
| **时间** | 会议时钟、设定时间、开始/暂停、流速（数字输入）、危机暂停 |
| **事件** | 公开/秘密事件、定时发布、危机、所有人/指定账号、已读、顶部弹窗、浏览器通知 |
| **文件** | 个人/代表团文件、文件类型、联署、阁首上传、个人文件权限、已读、下载 |
| **设置** | 会场创建/切换、默认规则、账号管理/席位绑定、线上存档、刷新、Web Push、分类清除 |

每个页面右上角都有会议时间戳；只有主席可以在「时间」页修改。
所有页面顶部有超链接导航：主页 / 席位 / 会期 / 投票 / 时间 / 事件 / 文件 / 设置。

## 二、多会场与账号

- 一个账号可属于多个会场；主席可在右上角或设置页切换。
- 会场只能由主席创建；创建者自动成为该会场主席。
- 每个会场可以有多个主席账号；代表账号只属于一个会场。
- 账号、席位、事件、文件、时间、存档均按会场隔离。

## 三、账号与权限

- 初始主席账号：**123456 / abcd**。部署后请立即在「设置 → 账号管理」重置密码。
- 代表账号由主席创建，可删除（初始主席 123456 不可删除），可绑定席位。
- 主席：全部编辑、时间控制、事件管理、查看全部文件、标记文件已读、账号管理、数据管理。
- 代表：可查看所有页面；可提交文件；可查看发给自己的事件并切换自己的已读；不能编辑任何会议数据。
- 删除代表团/席位不会删除账号，只会解除席位绑定。
- 所有写操作服务端二次校验角色。

主席从其他页面点击「事件」或「文件」时，会弹出：

> 是否确认进入事件界面？请确保未公屏投放给代表。

取消则留在原页面；代表进入不触发；直接输入 URL 不触发。

## 四、时间 / 事件 / 文件 / 主持

### 时间
- 服务端权威时间：`now_ms + rate + running + anchor`。
- 主席可设定当前时间、开始/暂停流动、输入阿拉伯数字设置流速（如 1、2、0.5、100）。
- 危机事件发布时立刻暂停时间；主席在时间页「解除危机暂停」后再手动开始。
- 定时事件按会议时间发布，不按现实时间。

### 事件
- 两类：**公开**（所有账号，包括主席团）与 **秘密**（只给选定代表账号）。
- 危机事件强制为公开事件。
- 已到时间自动发布；未到：主席看到「定时发布」。
- 公开/秘密事件都会在目标账号任意页面顶部弹窗；未读/已读可反复切换。
- 主席看到已读人数；公开事件的分母是所有账号。
- **浏览器通知**：设置页可申请通知权限；页面在后台标签页时收到新事件会弹系统通知。浏览器完全关闭时不保证送达。
- **无人打开网站时**：GitHub Actions 每 5 分钟调用 `/api/cron`，服务端按时发布到点事件。详见部署指南。
- 危机事件发布后暂停时间；取消危机标记会解除暂停状态（不自动恢复流动）。

### 文件
- 代表团可设置**阁首**；只有阁首（或主席团）能提交代表团文件。
- 文件分个人 / 代表团，选择文件类型；代表团文件可选**联署**。
- 主席团可在文件页开关「个人文件权限」；关闭时普通代表不能提交个人文件。
- 代表可看到自己的个人文件与本代表团的代表团文件；主席团看到全部。
- 文件 ≤2MB，存数据库。

### 会议主持
- 在「投票」前新增「会议主持」页。
- 动议类型可编辑：是否有主题、发言名单、总时长、单位时长。
- 默认：自由磋商、有主持核心磋商、自由辩论。
- 开启动议：选择动议国；按类型填写主题、总时长、单位时长，选择发言名单；支持实时倒计时与结束动议。

## 四、技术架构

```text
React 19 + Vite 8  ──fetch /api/*──▶  Hono 4（Vercel Serverless / Node）
                                          │
                                          ▼
                                   Turso（线上）/ .data/mun.db（本地）
```

- 认证：Cookie 会话（HttpOnly、SameSite=Lax、线上 Secure），密码 scrypt 加盐。
- 数据：`conferences` + `conference_members`；`conference_meeting` 保存每个会场的状态；`conference_time`；`events`/`files`/`archives` 均带 conference_id；账号与席位绑定在 membership；`sessions` 记录当前会场。
- 实时：前端默认每 **2 秒**轮询 `/api/bootstrap`；可在设置切换 2/5/10 秒；事件弹窗随轮询出现。
- 定时发布：GitHub Actions 定时调用 `/api/cron`（不依赖 Vercel Hobby 的每日 cron 限制）。
- 首次请求自动建表并写入初始主席账号，无需手动执行 SQL。

## 五、本地运行

要求 Node.js **22.18+**（推荐 24 LTS）。

```bash
pnpm install

# 终端 1：API（8787）
pnpm dev:api

# 终端 2：前端（5173，已代理 /api）
pnpm dev
```

打开 <http://127.0.0.1:5173>，使用 `123456 / abcd` 登录。
本地数据库：`.data/mun.db`；重置：停止 API，删除 `.data/`，重启 API。
生产构建：`pnpm build`（产物 `dist/`）。

当前预览：<http://127.0.0.1:5173>（API 8787 已启动）。

## 六、部署到 Vercel

Vercel 部署见 **[部署指南.md](部署指南.md)**；阿里云 ECS 部署见 **[部署指南-阿里云.md](部署指南-阿里云.md)**。

1. Turso 创建数据库，取得 `TURSO_DATABASE_URL` 与 `TURSO_AUTH_TOKEN`。
2. 项目推送到 GitHub，在 Vercel 导入（框架 Vite，build `pnpm build`，output `dist`）。
3. 在 Vercel 配置两个数据库环境变量；`CRON_SECRET` 可选。
4. Deploy；首次访问用初始主席账号登录，修改密码并创建代表账号。
5. GitHub Actions 会按 `.github/workflows/publish-events.yml` 每 5 分钟发布到点事件。

`api/index.js` 是构建时由 `server/vercel-handler.ts` 预打包的单文件入口，会作为 `/api` Serverless Function 部署；这样可以避免 Vercel 直接解析 `.ts` 依赖。

## 七、数据与安全

- 数据在 Turso，换设备登录同一网址即可继续。
- **线上存档**：设置 → 线上会场存档，包含会场名称、席位、会期、决议、设置、时间、账号与席位绑定、事件及已读、文件。
- **JSON 导出**只包含会议规则（主题、席位、会期、决议）；完整备份请用线上存档。
- **分类清除**：选择会场信息、席位、会期/决议、会议主持、时间、事件、文件、账号等类别；只影响当前会场，线上存档作为备份保留。
- 文件占数据库空间，单文件 ≤2MB；会后请主席下载留存。
- 不要把主席页面投屏给代表；直接输入事件/文件 URL 不会触发确认弹窗。
- 代表只能提交文件、查看页面、切换自己的事件已读状态。

## 九、已知边界

- 轮询默认 2 秒，可在设置改 5/10 秒；不是 WebSocket。
- 无人打开网站时依赖 GitHub Actions 每 5 分钟调用 `/api/cron`，发布精度约 5 分钟。
- 浏览器通知要求页面至少有一个标签页打开；完全关闭浏览器需要 Web Push，当前版本不做。
- 文件 ≤2MB，无预览、无删除、无版本；完整存档会包含文件，体积随文件增长。
- 只有一个主席角色；代表不能自行改密码，需主席重置。
- 无审计日志、撤销、回收站；分类清除不可撤销，线上存档可保留恢复。
